# The Last Floor — UI-демо на Unreal Engine 5

Интерфейс для roguelite про восхождение на башню: главное меню, HUD, экран реликвий
с drag&drop, пауза с вкладками и экран итогов забега. Геймплея нет: состояние забега
меняет тестовая панель кнопок прямо в HUD. Цель проекта — показать полный UMG-пайплайн:
вёрстку, анимации, данные из таблиц, работу с фокусом и вводом, и связку Blueprint с C++.

## Экраны

### Главное меню

- Кнопки — один переиспользуемый `WBP_MenuButton`: 9-slice-кисти на четыре состояния,
  hover и нажатие анимированы через `Render Transform` (без перестройки лейаута).
- `CONTINUE RUN` активна, только пока идёт забег: флаг уровня профиля в Game Instance.
- `SETTINGS` — заглушка.

### HUD

![HUD](Docs/Media/hud.png)

- Базовый класс на C++ (`UHUDWidget`) связан с виджетами через `meta = (BindWidget)`:
  если в `WBP_HUD` нет нужного прогресс-бара или текста, Blueprint не скомпилируется.
- HUD подписан на делегат `OnStatsChanged` и перерисовывается только при изменении статов,
  без `Tick` и без привязок свойств (Property Binding).
- C++ решает, *когда* здоровье стало низким (`BlueprintImplementableEvent OnLowHealthChanged`),
  Blueprint решает, *как* это выглядит: баннер угрозы выезжает, сердце пульсирует.
- Иконки — спрайты из одного атласа.
- Тестовая панель лежит в `Invalidation Box`: статичный UI не перерисовывается каждый кадр.

### Реликвии

![Реликвии](Docs/Media/relics.png)

- Сетка 4×4 строится из Data Table `DT_Relics` (16 строк, структура `S_RelicData`,
  перечисление редкости). Ключ — Row Name, тексты — локализуемые `Text`.
- Иконки — soft-ссылки, загружаются асинхронно (`Async Load Asset`) при показе ячейки.
- Тултип — отдельный виджет `WBP_RelicTooltip` (название, редкость, описание).
- Drag&drop на переопределениях `UUserWidget`:
  - из сетки в слот экипировки — копия;
  - между слотами — перенос или обмен;
  - бросок мимо слотов — снять реликвию.
- Правило «одна реликвия — один слот» живёт в C++-компоненте, а не в виджете,
  поэтому ни один экран не может его нарушить.
- Цвет и подпись редкости — в `BPFL_Relics` (Blueprint Function Library), одно место для всех экранов.

### Пауза

![Пауза](Docs/Media/pause.png)

- Слой поверх текущего экрана (`ZOrder 10`), а не новый экран: HUD остаётся под затемнением.
- Вкладки RUN / RELICS / CONTROLS — `Widget Switcher`; на вкладках переиспользуются те же
  виджеты строки статистики и слота реликвии.
- `Set Game Paused` останавливает игровое время, UI продолжает работать.
- Открывается и закрывается клавишей **P** (`OnKeyDown`) и кнопкой.

### Итоги забега

![Итоги](Docs/Media/results.png)

- Числа «набегают» по таймеру: значение считается от абсолютного времени с ease-out cubic,
  в конце — короткий «поп» масштабом. Строки стартуют с задержкой одна за другой.
- Моноширинные цифры, чтобы число не дрожало по ширине во время счёта.

## Архитектура

**Состояние живёт не в виджетах.** Экраны создаются и уничтожаются при каждом переходе,
поэтому данные забега лежат в компонентах на Player Controller:

| Компонент | Что хранит |
|---|---|
| `UStatsComponent` (C++) | здоровье, энергия, валюта, этаж; делегат `OnStatsChanged` |
| `URelicLoadoutComponent` (C++) | три слота экипировки; делегат `OnLoadoutChanged` |

Схема «модель — вид — команда»: виджет просит компонент изменить состояние, компонент
проверяет правила и рассылает событие, все подписанные виджеты перерисовываются.
Подписка — в `Construct`, отписка — в `Destruct`.

**Три времени жизни состояния:**

| Уровень | Где | Пример |
|---|---|---|
| экран | переменные виджета | подсветка слота во время перетаскивания |
| забег | компоненты контроллера | статы, экипировка |
| профиль | Game Instance | флаг «забег идёт» для `CONTINUE RUN` |

**Менеджер экранов** — в `BP_TheLastFloorPlayerController`:

- `SwitchToScreen(Class)` — один активный экран, режим ввода `UI Only`, фокус на новом экране;
- `OpenPause` / `ClosePause` — слой поверх экрана с возвратом фокуса.

В продакшене эту роль выполнил бы плагин **CommonUI** (стек activatable-виджетов);
здесь менеджер написан руками, чтобы были видны фокус, слои и режимы ввода.

**Разделение Blueprint / C++:**

| C++ | Blueprint |
|---|---|
| статы и правила экипировки (компоненты с делегатами) | вся вёрстка и стили |
| `UHUDWidget`: `BindWidget`, подписка на статы, событие низкого здоровья | анимации, переходы, drag&drop |
| | данные реликвий (struct + Data Table, без C++) |

## Структура проекта

```
Source/TheLastFloor/
  StatsComponent            статы забега + OnStatsChanged
  RelicLoadoutComponent     слоты экипировки + OnLoadoutChanged
  HUDWidget                 C++-база для WBP_HUD (BindWidget)
Content/
  Core/                     Game Mode, Game Instance, Player Controller (менеджер экранов)
  Data/                     S_RelicData, E_RelicRarity, DT_Relics
  UI/Common/                WBP_MenuButton, BPFL_Relics
  UI/Menu/  UI/HUD/  UI/Relics/  UI/Pause/  UI/Results/
  Textures/                 фоны, 9-slice-панели, атласы иконок
Tools/generate_art.py       генератор всего UI-арта
```

## Арт

Все текстуры — фоны, 9-slice-панели и кнопки, атласы иконок и спрайты реликвий —
сгенерированы скриптом [`Tools/generate_art.py`](Tools/generate_art.py) (Python, Pillow, NumPy).
Палитра задана в одном месте, весь набор перегенерируется одной командой.
Список файлов и 9-slice-поля — в [`Docs/ArtManifest.md`](Docs/ArtManifest.md).

## Запуск

**Готовая сборка:** скачать архив из [Releases](https://github.com/Murted/the-last-floor-ue5-ui/releases/latest), распаковать,
запустить `TheLastFloor.exe`. Нужна Windows 10/11 x64.

**Из исходников:**

1. Unreal Engine 5.8, Visual Studio 2022 с компонентом «Разработка игр на C++», Git LFS.
2. `git lfs install`, затем `git clone` — ассеты лежат в LFS.
3. Правый клик по `TheLastFloor.uproject` → *Generate Visual Studio project files*,
   открыть `.uproject` и согласиться пересобрать модуль.

Плагины в `.uproject` (`ModelContextProtocol` и наборы инструментов) — редакторные,
поставляются с UE 5.8 и в сборку игры не попадают.

## Как делался проект

Проект сделан вместе с ИИ-ассистентом (Claude Code) — отсюда строки `Co-Authored-By` в коммитах.

- **Сам, в редакторе:** вёрстка и Blueprint-логика главного меню, HUD и экрана реликвий —
  виджеты, стили и анимации, переходы между экранами, Data Table реликвий, тултипы,
  drag&drop. Ассистент работал наставником: объяснял концепции UE и предлагал решения,
  я реализовывал их, отлаживал и тестировал.
- **Ассистент:** C++-классы (компоненты статов и экипировки, `UHUDWidget`) с разбором кода;
  экраны паузы и итогов — из-за сроков собраны ассистентом через MCP-мост к редактору,
  я ставил задачу, проверял и тестировал; генератор арта `Tools/generate_art.py`.
